# Catwalk / hull-plate fix — salvageshuttle recreation

Status: **fixed, re-baked, re-rendered, vision-verified.** Working tree left uncommitted (project standing rule: no commits, no pushes).

## 1. Defect

In the baked scene (`Assets/Scenes/HomeShip.unity`) the catwalk strip rendered as dark cells with a
small grate decal occupying roughly one quarter of each tile, so the hull plating beneath the strip
read as "not visible" / near-black. Same for the two airlock strips.

## 2. Root cause (measured, not inferred)

The layout TSV `Assets/ShipData/salvageshuttle.layout.tsv` (the bake's *input*, read by
`Assets/Editor/SalvageShuttleBake.cs`, `LayoutPath`) carried **130 catwalk rows across 26 tiles** —
5 rows per tile, one per imported `Catwalk/catwalk_{0-4}.png` piece — and each tile's pieces were
given individual rotations:

| rot (pre-fix) | rows |
|---|---|
| 0     | 52 |
| −90   | 26 |
| −180  | 26 |
| −270  | 26 |

Those pieces are partial-tile grate art meant to be assembled in one orientation. Rotating each piece
of a tile independently displaced the grate pixels, so only a quarter of every tile carried grate art.

Quantified by re-implementing the bake in PIL (`sim_catwalk.py`) against the pre-fix TSV backup:

| per catwalk tile (32×32 px = 1024) | pre-fix | post-fix |
|---|---|---|
| opaque pixels | 256 (25 %) | 1024 (100 %) |
| fully opaque pixels | 207 | 807–821 |

**26 / 26 tiles changed.** Rows changed: **130** (all catwalk rows, rot → 0). No other row was touched:
the remaining 513 rows keep their rotations (histogram after fix: 0×462, −90×55, −180×55,
−270×55, +270×7, +90×6, +180×3). Total rows 643 = 643 baked layers.

## 3. Fix

Data-only, one field: `rot` := 0 for the 130 catwalk rows (script
`apply_catwalk_rot_fix.py`; pre-fix TSV backed up to
`~/.hermes/profiles/coder/cache/scratch/layout_backup_20261118_201218.tsv`).
No source pixels repainted, no recolouring, no new sprites, no duplicate plating added —
the imported `catwalk_0..4` states are used as-is, in their intended orientation.
